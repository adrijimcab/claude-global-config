# Lessons Ledger — past mistakes, do NOT repeat

Append-only log of errors and the rule that prevents repeating them.
Loaded once per session by `~/.claude/rules/20-lessons.md` (an `@` import), in EVERY project. The
`[b100-am-ui]` lessons live in `<b100-am-ui>/.claude/lessons-ledger.md`, loaded only there.

**Format (one line per lesson, keep it tight):**
`- [scope] YYYY-MM-DD — What went wrong → root cause → RULE to not repeat.`

- `scope` = project name (`[b100-am-ui]`) or `[global]` when it applies everywhere.
- Keep each entry to ONE line. Long detail goes to normal memory, link it.
- Curate: if a lesson is superseded or wrong, edit/remove it — this file is loaded into every context, so noise costs tokens.
- ONE entry per RULE, never per incident: a repeat FOLDS into the existing entry keeping the EARLIEST date and carrying `(×N)`. A rule that recurred nine times is stronger evidence than one that fired once — that signal must survive the merge, so never flatten it away.
- An HTML comment of the form `fc:KEY#N` at the end of a line is machine state owned by `.claude/failure-capture/` (one key per LINE, first marker on the line wins, `n` = incidents in `incidents.jsonl`). Never edit, duplicate or move a marker off its line; a `(×N)` in the prose may exceed `n` when pre-loop manual entries were folded in.
