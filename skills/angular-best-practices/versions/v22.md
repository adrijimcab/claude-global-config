# Angular 22 — delta over the official rules

Measured 2026-10-06 from `angular/angular` branch `22.2.x` (HEAD after v22.2.1), `angular/angular-cli` branch
`22.2.x` and `npm view`. Citation key as in `v19.md` (`A22:`, `C22:`, `UR:`).

**Read first:** `node_modules/@angular/core/resources/best-practices.md` (59 lines in 22; MCP
`get_best_practices` reads it). Versus 21 it adds: no explicit OnPush, `model()`, `linkedSignal()`, Signal
Forms, no `CommonModule`, `@Service`. This file carries only what it lacks.

## Status

- Released 2026-06-03; current 22.2.1 (2026-09-30). **Active until 2027-06, LTS until 2028-06.** From 22 the
  major cadence is 12 months (`A22:releases.md:63-69`); v23.0 is expected around June 2027.
- TypeScript `>=6.0 <6.1` (6.0 only; `typescript@latest` 7.0.x is outside the range); Node
  `^22.22.3 || ^24.15.0 || >=26.0.0`. angular-eslint line: 22.5.0 (adds `prefer-service-decorator`).
- Docs for this major: `https://github.com/angular/angular/tree/22.2.x/adev/src/content` (= angular.dev today).

## Defaults that flipped in 22 — do NOT write the old opt-ins

| Was | In 22 | So |
|---|---|---|
| `changeDetection: OnPush` explicit | OnPush is the default; `ChangeDetectionStrategy.Default` is a deprecated alias of `Eager` | omit OnPush; write `Eager` only where the old strategy is deliberately kept (`ng update` adds `Eager` to existing components: review and remove where OnPush works) |
| `provideHttpClient(withFetch())` | Fetch backend is the default; `withFetch` deprecated; `withXhr()` opt-in | omit `withFetch()`; `withXhr()` only where upload progress is needed, never on SSR (XHR on the server deprecated, removal planned for v23) |
| `withIncrementalHydration()` | incremental hydration default with `provideClientHydration()`; opt-out `withNoIncrementalHydration()` | omit it |
| `strictTemplates` opt-in | `true` by default (`ng update` writes `strictTemplates: false` where unset) | remove that `false` and fix the template errors: keeping it is a suppression |
| `?.` yields `null` | `?.` yields `undefined`, with nullable narrowing | run the migration; `$safeNavigationMigration()` marks templates that relied on `null` |

## Newly stable in 22 — use them

`resource`, `rxResource`, `httpResource` (`@publicApi 22.0`): async reads into signals; use `chain`, not
`undefined` params (`A22:guide/signals/resource.md:205`); never for mutations (a param change aborts the
load). Signal Forms (`@publicApi 22.0`): prefer for NEW forms; existing reactive forms stay until a decided
migration. `@Service()` decorator: prefer for new root singletons (`ng g @angular/core:service`; docs say the
schematic arrives in 22.1, the changelog puts `@Service` in 22.0). Angular Aria stable. Expression-body arrow
functions in templates (`A22:expression-syntax.md:85-89`).

## Still EXP/DP in 22 — avoid by default

`debounced()` (EXP), `@boundary` error boundaries (DP), `resourceFromSnapshots` (EXP), `withViewTransitions`
(DP), WebMCP tools (EXP).

## Deprecated or removed in 22

Deprecated: `withFetch`, `withIncrementalHydration`, `reportProgress` (22.0: use `reportUploadProgress`/`reportDownloadProgress`), `withJsonpSupport`/JSONP (22.1),
webpack builders, `CommonEngine` (use `AngularNodeAppEngine`/`AngularAppEngine`),
`ChangeDetectionStrategy.Default`, `provideAnimations*`, `NgIf`/`NgFor`/`NgSwitch` (still exported).
Removed: `provideRoutes()`, `ComponentFactoryResolver`/`ComponentFactory`, `createNgModuleRef`,
`ChangeDetectorRef.checkNoChanges()`, Hammer.js integration, `@angular-devkit/architect-cli`,
`build-angular:jest` and `build-angular:web-test-runner`. Behaviour: `paramsInheritanceStrategy` defaults to
`"always"`; `CanMatchFn`'s third argument `currentSnapshot` is required; `data-*` attributes no longer bind to
inputs/outputs; duplicate selectors or bindings are compile errors; unused component styles are dropped.

## Updating to 22 (from 21)

`ng update @angular/core@22 @angular/cli@22`. Migrations (`A22:packages/core/schematics/migrations.json`):
`change-detection-eager`, `http-xhr-backend`, `strict-templates-default`, `can-match-snapshot-required`,
`incremental-hydration`, `strict-safe-navigation-narrow`, `model-output`, `safe-optional-chaining`. CLI (C22):
`add-istanbul-instrumenter`, `use-application-builder`, `migrate-karma-to-vitest`, `trust-proxy-headers`,
`update-workspace-config`. New optional `ng generate @angular/core:service-migration` (alias `service`).

Update-guide actions (UR L2967-3258): Node 22.22.3/24.15+, TypeScript >= 6.0; `withXhr()` only where upload
progress is needed; set `Eager` only where the old change detection is needed; fix strict-template errors
instead of opting out; review `$safeNavigationMigration()` sites; Karma coverage needs an explicit
`istanbul-lib-instrument` (migration `add-istanbul-instrumenter`); leave webpack builders and `CommonEngine`.

## Project conventions in 22

- `migrate-karma-to-vitest` exists, but the Vitest migration guide still calls it experimental
  (`A22:guide/testing/migrating-to-vitest.md:5`): a Karma project stays on Karma unless the move is decided.
- The `Eager` markers `ng update` adds are debt to burn down, not a convention to copy into new components.

## Idiomatic v22 component

```ts
import { Component, computed, input, model } from '@angular/core';
import { httpResource } from '@angular/common/http';

export interface Customer {
  readonly id: string;
  readonly name: string;
}

@Component({
  selector: 'app-customer-picker',
  templateUrl: './customer-picker.html',
})
export class CustomerPicker {
  readonly query = input('');
  readonly selectedId = model<string | undefined>(undefined);
  protected readonly customers = httpResource<readonly Customer[]>(() => `/api/customers?q=${encodeURIComponent(this.query())}`);
  protected readonly count = computed(() => this.customers.value()?.length ?? 0);
}
```

No `changeDetection` (OnPush by default), `model()` instead of an input + output pair, `httpResource` stable.
