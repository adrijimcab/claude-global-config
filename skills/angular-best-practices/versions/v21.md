# Angular 21 — delta over the official rules

Measured 2026-10-06 from `angular/angular` branch `21.2.x` (v21.2.25), `angular/angular-cli` branch `21.2.x`
and `npm view`. Citation key as in `v19.md` (`A21:`, `C21:`, `UR:`).

**Read first:** `node_modules/@angular/core/resources/best-practices.md` — the official rules for the exact
installed version (shipped inside `@angular/core` from 21.0.0; `package.json` field `angular.bestPractices`; the
MCP tool `get_best_practices` reads the same file). This file carries only what that file lacks: gating,
migrations, deprecations, update-guide actions and project-convention caveats.

## Status

- Released 2025-11-19; last patch 21.2.25 (2026-09-30). Active support ended 2026-06-03; **LTS until 2027-06**.
- TypeScript: `@angular/compiler-cli` peer `>=5.9 <6.1` (21.2 added TypeScript 6), but `@angular/build@21.2.25`
  still peers `<6.0` and the docs table says `<6.0`: stay on 5.9 unless the build accepts 6.0 in this project
  (UNVERIFIED which one the toolchain enforces). Node `^20.19.0 || ^22.12.0 || >=24.0.0`; zone.js
  `~0.15.0 || ~0.16.0`. angular-eslint line: 21.4.0 (adds `prefer-signal-model`; verified in the tarball).
- Docs for this major: `https://github.com/angular/angular/tree/21.2.x/adev/src/content`.

## Gating in 21 (what the official file does not say)

| API | Status in 21 | Rule |
|---|---|---|
| Zoneless | DEFAULT for new apps | A zone-based app must call `provideZoneChangeDetection()` explicitly after the update |
| `resource`/`rxResource`/`httpResource` | EXP | avoid (stable in 22.0) |
| `resourceFromSnapshots` | EXP (21.2) | avoid |
| Signal Forms | EXP; API churn 21.1-21.2 (`[formField]`/`FormField`, `SignalFormControl`) | avoid; typed reactive forms |
| Angular Aria | DP | avoid unless decided |
| MCP `build`/`test`/`e2e`/`modernize`/`devserver.*` | EXP | not relied on |
| `ChangeDetectionStrategy.Eager` | alias of `Default` from 21.2 | `OnPush` is still written explicitly in 21 |
| Arrow functions in templates | expression body from 21.2 | allowed only on 21.2+; the 21 rules dropped the old ban |
| `@switch` multi-case (21.1), exhaustive `@switch` (21.2), spread/rest (21.1), `instanceof` (21.2) | new template syntax | only on the minor that has it |

## New in 21

Vitest is the `ng new` default (`testRunner: vitest`, builder `@angular/build:unit-test`; Karma still supported;
schematic `refactor-jasmine-vitest` is EXPERIMENTAL); host-binding type checking on by default; option
`fileNameStyleGuide` (default `2025`); `FormArrayDirective`; `lastSuccessfulNavigation` signal;
`ApplicationConfig` moved to `@angular/core`; MCP gains stable `ai_tutor`, `find_examples`,
`onpush_zoneless_migration`.

## Deprecated or removed in 21

Deprecated: `ApplicationConfig` from `@angular/platform-browser` (import from `@angular/core`); `interpolation`
and `moduleId` in `@Component`; `ignoreChangesOutsideZone`; `Router.getCurrentNavigation()`. Removed:
`UpgradeAdapter`, `NgModuleFactory`. `audio[src]` is no longer sanitized.

## Updating to 21 (from 20)

`ng update @angular/core@21 @angular/cli@21`. Migrations (`ng update` 21.0.0): `control-flow-migration`,
`router-current-navigation`, `router-last-successful-navigation`, `application-config-core`,
`add-bootstrap-context-to-server-main`, `bootstrap-options-migration`. CLI: `use-application-builder`,
`remove-default-karma-config`, `update-typescript-lib`, `update-module-resolution`.

New optional `ng generate @angular/core:<name>` in 21 (`A21:packages/core/schematics/collection.json`):
`common-to-standalone`, `ngclass-to-class`, `ngstyle-to-style`, `router-testing-module-migration` (plus the 19/20
set).

Update-guide actions (UR L2775-2965): TypeScript >= 5.9; **add `provideZoneChangeDetection()` if the app stays
on zone.js** (otherwise it becomes zoneless and change detection silently stops where it relied on zone);
remove `moduleId`/`interpolation`; fix host-binding type errors (the escape `typeCheckHostBindings: false` is a
suppression: forbidden by the owner mandates); TestBed rethrows errors; `PlatformLocation` is faked in tests
(restore with `MockPlatformLocation` only where a test needs the real one); router navigations take extra
microtasks (await them); SSR: `CommonEngine({ allowedHosts })` from `@angular/ssr` 21.1.5 (GHSA-x288-3778-4hhx,
backported to 20.3.17 and 19.2.21); signal inputs on custom elements are read directly.

## Project conventions in 21

- A project updated from 20 keeps its zone.js unless the zoneless move is decided (and tested: the MCP
  `onpush_zoneless_migration` tool or `angular.dev/guide/zoneless` steps: remove `zone.js` and
  `zone.js/testing` from build and test polyfills, uninstall, all components OnPush-compatible).
- A Karma project stays on Karma; a Jasmine-to-Vitest refactor is its own change.
- File naming follows `fileNameStyleGuide` in `angular.json` and the existing files.

## Idiomatic v21 (delta only)

```ts
// Zone-based app kept on zone.js after updating to 21: say so explicitly.
export const appConfig: ApplicationConfig = {
  providers: [provideBrowserGlobalErrorListeners(), provideZoneChangeDetection({ eventCoalescing: true }), provideRouter(routes)],
};
```

`ApplicationConfig` imports from `@angular/core` (migration `application-config-core`).
