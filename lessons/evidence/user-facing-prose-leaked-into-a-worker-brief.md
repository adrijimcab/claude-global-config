## Ledger line archived 2026-10-01 (condensed)

- [global] 2026-09-09 — My status report to the OWNER was delivered to a worker as part of its instructions. Measured: the sdd-tasks agent's prompt ended with several paragraphs of Spanish prose written for the owner -- parity anchor counts, how many agents were running, which tasks had returned to the backlog, and a closing question 'shall I launch them, or do you want to see them first?' addressed to the owner. The owner spotted it in the agent's own transcript and said it must not happen again. ROOT CAUSE: I began writing the user-facing reply INSIDE the still-open parameter block of the Agent tool call instead of closing the call first, so the prose was captured as part of the prompt argument. The XML structure of my own output is what carries the audience boundary, and I broke it. WHY IT MATTERS BEYOND TIDINESS: a worker cannot tell my report to the owner from my instructions to it. Orchestration state -- agent counts, anchor totals, backlog changes -- is noise that can steer a brief, and a question addressed to the owner sitting in a worker's prompt invites the worker to answer it or act on it. It is the mirror image of the brief-provenance defect: there I laundered guesses into a worker as facts, here I laundered a conversation with someone else into a worker as instructions. RULE: the user-facing reply is written only AFTER every tool call in the turn is closed, never inside one. Before sending any brief, the last thing in the prompt must be an instruction to the worker -- if the final paragraph addresses anyone but the worker, the block is malformed and must not be sent. And when it happens anyway, correct the live worker immediately and name which part to discard rather than hoping it ignored it. <!--fc:user-facing-prose-leaked-into-a-worker-brief#1-->
